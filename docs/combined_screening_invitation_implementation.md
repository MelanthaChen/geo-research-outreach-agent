# Combined GEO screening and invitation drafting

Date: 2026-10-22

## Implementation

`src/outreach_agent/combined_screening.py` provides the single analysis service used by the Research Queue. It fetches a bounded set of public pages through the existing preliminary-screening fetcher, retains the page evidence in the registry, and produces one validated envelope containing:

- source pages and captured evidence;
- GEO signals, opportunities, realistic customer questions, rating, limitations, and one or two talking points;
- a company-specific research invitation subject and body;
- mode, provider/model metadata, prompt version, content hash, and token/cost fields.

`RULE_BASED`, `LOCAL_LLM`, and `PAID_API` are explicit modes. Rule-based mode makes no model call. Local and paid modes require the existing explicit provider configuration; local mode rejects known paid hosted endpoints and no mode silently falls back to another provider.

## Persistence and review controls

The analysis envelope, screening record, secure questionnaire invitation, and email draft are written in one registry transaction by `persist_combined_screening_and_draft`. The content hash and `(profile, mode)` uniqueness rule make retries idempotent. Questionnaire tokens are generated and stored as hashes while the opaque token is placed only in the draft URL.

Drafts are always created as `PENDING`. Opening an existing record reads the stored result and draft; it does not fetch pages or invoke an analysis provider. Human approval remains a separate lifecycle action. Manual draft editing resets approval to `PENDING` and updates the preview hash.

## Dashboard/API

- `POST /api/recruitment/screen-and-draft` runs the combined service. It accepts `profile_id`, recipient, explicit mode, and the configured questionnaire base URL.
- `POST /api/recruitment/draft/{draft_id}/edit` supports reviewed manual edits and returns the draft to pending approval.
- Existing approval and simulated-send endpoints remain unchanged and retain their safety gates.

The invitation uses observed website evidence and describes opportunities as preliminary research observations. It contains no fabricated visibility measurements, rankings, citations, or guaranteed improvements. The questionnaire URL is generated by the existing secure invitation workflow.

## Verification

The combined-path test verifies that the first rule-based run performs one fetch and zero AI calls, persists both outputs, and leaves the draft pending. A repeat run reuses cached evidence and is idempotent. Approval changes registry state without another provider call. The full test suite was run locally after this implementation; no paid provider, email delivery, deployment, commit, or push was performed.
